# BhuVistaar — Prototype Interoperability Specification

**Document Version**: 1.0.0  
**Scope**: Structured Export, 2D GeoJSON, 3D Wavefront OBJ, and Deterministic Provenance Verification  
**Standard Status**: Prototype Interoperability Format (NOT an official Government 3D ULPIN standard)

---

## 1. Disclaimer & Standard Status

> [!CAUTION]
> **PROTOTYPE INTEROPERABILITY FORMAT**  
> Identifiers generated by BhuVistaar (e.g. `BV-12345678901234-BLDG-L01-9B2F01`) are **Prototype Volumetric Unique Identifiers (VUID)** and are **NOT official statutory 3D ULPINs**.  
> This specification defines a machine-readable data exchange contract for research, evaluation, and pilot simulation. It does not replace statutory cadastral registration or official land title adjudication.

---

## 2. Supported Export Formats

BhuVistaar provides three interoperability outputs tailored for different downstream GIS, CAD, and operational consumers:

| Format | Endpoint | Intended Consumer | Semantic Fidelity |
|:---|:---|:---|:---|
| **Structured JSON v1.0.0** | `GET /api/v1/export/units/{revision_id}` | Cadastral registries, audit verification, round-trip re-ingestion | **Full 3D Volumetric Fidelity** + Provenance, Validation & Governance |
| **2D GeoJSON FeatureCollection** | `GET /api/v1/export/geojson/{ulpin}` | QGIS, ArcGIS, WebGIS mapping engines | **Planar Footprint** with 3D attributes (`z_min`, `z_max`, `volume_cbm`) |
| **3D Wavefront OBJ** | `GET /api/v1/export/3d/{revision_id}` | Blender, Three.js, Cesium 3D Tiles, BIM tools | **Triangulated 3D Polyhedron Mesh** with closed top/bottom caps |

## 4. Deterministic VUID Generation & Invariance

To guarantee reproducibility across systems, the Prototype VUID is generated using canonical geometry normalization:

```
VUID Input Buffer:
  {algorithm_version}|{parent_ulpin}|{unit_class}|{level_code}|{canonical_wkb_hex}|{z_min:z_max}
```

### Invariance Properties:
1. **Starting Vertex Independence**: Exterior polygon boundary rings are cyclically shifted to the lexicographically minimal vertex.
2. **Winding Order Normalization**: Exterior rings are normalized Counter-Clockwise (CCW); interior rings (holes) are normalized Clockwise (CW).
3. **Deterministic Hole Ordering**: Multiple interior holes are sorted deterministically by centroid coordinates.
4. **Coordinate Precision Normalization**: All coordinates are rounded to 3 decimal places (1mm spatial precision).

## 5. Import → Export Round-Trip Verification

Downstream consumers can verify that an exported BhuVistaar package retains cryptographic and geometric integrity using the round-trip verification API:

`POST /api/v1/export/roundtrip/verify`

The verification engine checks:
1. **Schema Completeness**: All mandatory top-level blocks exist.
2. **Checksum Integrity**: Re-hashes polygon coordinate arrays and compares with claimed provenance checksums.
3. **VUID Determinism**: Re-runs the canonical VUID generator against the geometry and vertical bounds; confirms that `recalculated_vuid == claimed_vuid`.
4. **Discrepancy Audit**: Emits an audit event (`IMPORT_COMPLETED`) recording whether verification succeeded or failed.

---

## 6. Limitations & Non-Supported Capabilities

1. **CityGML ADE**: Official CityGML Cadastral ADE is not implemented in this prototype.
2. **IFC 4x3 Cadastral Extension**: Direct building-BIM IFC exchange is planned for future phases.
3. **Unprojected Global Geographic CRS**: Export in unprojected `EPSG:4326` is restricted to 2D viewports with warnings, as planar volumetric extrusion requires projected metric reference systems (e.g. `EPSG:32643`).
